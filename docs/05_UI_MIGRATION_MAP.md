# 06. 기존 역할과 UI v3의 개정 지도

이번 작업은 개발 계획 개정이다. 기존 `field_ui_prototype_v3.html`을 새 제품 구조로 재구현했다고 표시하지 않는다. 기존 디자인·사이트 제작·고객·사업자·매체·관리자 기능을 보존하되 소유 제품과 이동 경로를 아래처럼 고친다.

## 6.1 역할·제품별 화면

| 기존 항목 | 개정 소유 제품 | 수정할 흐름 |
|---|---|---|
| Field 플랫폼 홈 | Field | ‘홈페이지 만들기’ 중심, ‘AI만 도입’은 별도 AP 제품으로 안내 |
| AI만 도입하기 | AP 홈페이지/개설실 | Field 가입·사이트·예약을 요구하지 않음 |
| 사업자/서비스 제공자/광고주 | 각 제품 owner | 불필요한 3개 역할 계정은 만들지 않되 AP/Field 조직·동의는 별도 |
| 셀프 사이트 5단계 | Field | 원래 기능 유지, AI 상담 연결은 선택 단계 |
| 내 사이트 / 제작 AI | Field | 자체 제작 LLM·초안·공개·복구 |
| 내 사업 AI | AP | 지식·응대 테스트·설치·활성화·사용량 |
| Field의 AI 메뉴 | Field 연동 서비스 | 연결/권한/동기화/설치 상태·AP 관리실 이동 |
| 홍보 카드·공유·매체 배치 | AP | 자체 위젯 설치와 광고 캠페인을 분리 |
| 문의함 | 양쪽 각각 | Field는 자기 직접 대화+허용된 AP 목록을 합성; AP 원문은 공식 API |
| 예약·달력 | Field | AP에서 요청은 가능하지만 원본·확정은 Field |
| 고객 AI 상담·후속 대화 | AP | AP 도메인·권한·알림, Field 예약 상세는 안전 handoff |
| 고객 직접 문의·예약 | Field | AP 없어도 기존 양식/통화/후속 대화 유지 |
| 제휴 매체 | AP | 위치·배치·승인·집계, Field 고객 데이터 열람 불가 |
| 플랫폼 관리자 | AP admin / Field admin | 각각 권한·MFA·로그·구독·운영 장애. 통합 superuser 금지 |

## 6.2 Field에 표시할 연결 화면의 필수 상태

| 상태 | 표시 | 행동 |
|---|---|---|
| 미연결 | ‘AI 상담은 별도 서비스를 연결해 이용합니다’ | 계정 연결 / AP 가입 / 나중에 |
| 설치만 연결 | ‘AI 상담 사용 중 · 예약 연동 없음’ | Field 정보/예약 권한 추가 승인 |
| 정보 검토 필요 | 변경된 서비스·가격·영향 접점 | AP 정보 검토로 이동 |
| 사용 가능 | 선택 AI·배포 주소·권한·마지막 검증 | 테스트 / 설정 / AP 관리실 |
| 일시 장애 | 직접 문의·예약 정상, AI 또는 원격 대화 제한 | 상태 확인 / 직접 문의 경로 |
| 해제 중 | 로컬 차단 완료·원격 토큰 회수 대기 | 기존 예약 처리·알림 경로 점검 |
| 해제 | Field 업무는 유지, AP 원문 접근은 없음 | 재연결 / AP 직접 관리실 안내 |

## 6.3 승인/정상 상태를 과장하지 않는다

‘연결됨’은 모든 source가 최신 승인이라는 뜻이 아니다. ‘요청 저장’은 외부 Field 접수 완료가 아니며, 외부 접수도 예약 확정이 아니다. ‘원격 이벤트 수신’은 고객 알림 전달이 아니다. 외부 callback 대기나 stale 상태를 초록 체크 하나로 대체하지 않는다.

AI가 설치되지 않은 Field 사이트에는 동작하지 않는 ‘AI에게 문의’ 버튼을 노출하지 않는다. 실제 앱에서 시안 상단 역할 탭은 제거하고 로그인·권한별 제품 라우팅을 적용한다. 검토용 UI가 필요하면 별도 데모 배너와 합성 데이터 환경에 한정한다.

## 6.4 디자인 계약 유지

Apple 계열의 단순한 화이트·밝은 그레이, 시스템 폰트, 여백, 블루 주요 행동, 최소 경계를 유지한다. 모든 표시 텍스트 최소14px, 본문/입력16px, 조작 영역44px급을 지향한다. 외부 위젯도 14px 미만으로 축소하지 않는다. macOS/iOS 기본 폰트를 참조하되 폰트 파일을 배포하지 않는다.

320/390/768/1440px·200% 확대·키보드·스크린리더·동작 감소를 검수한다. Field 모바일 오늘/문의/예약/내 사이트/더보기는 유지한다. AP 모바일은 AI/문의/설치/더보기 중심으로 별도 구성하고, 매체도 운영/위치/요청/성과/설정을 유지한다. 화면마다 빈 상태·저장·오류·미연결·권한 거부·한도·동기화 지연을 구현한다.

## 6.5 실제 사용자 인수 시나리오

**외부 사업자:** AP 가입 → 직접 정보 등록 → AI 승인 → Field와 무관한 기존 사이트 설치 → 고객 질문 → AP 문의함에서 답변 → AP 구독.

**Field만 쓰는 사업자:** Field 가입 → 자기 사이트 제작 → 공개 → 직접 문의와 두 예약 방식 → 자체 알림 → Field 구독. AP가 없다는 이유로 메뉴를 막지 않음.

**두 제품을 쓰는 사업자:** 각 제품의 조직·요금 확인 → 공식 연결 승인 → Field 공개 정보 동기화 검토 → 같은 AP SDK 설치 → 고객 상담 → Field 업무 요청 → Field 관리실에서 API 답변·예약 승인 → 고객은 원래 대화에서 결과 확인.

**매체:** AP 매체 조직 → 도메인/위치 확인 → 사업자 공개 카드의 정확한 버전 승인 → 별도 origin에서 표시 → AP 안전 접수 → 집계만 조회. Field가 없어도 일반 상담 광고 실험 완료.

**운영자:** 제품별 콘솔 → 자기 권한 범위의 장애/신고 확인 → 사유·기간·증빙으로 조치 → 연동 문제는 correlation_id와 최소 메타데이터로 협업. 관리자 세션을 다른 제품에 그대로 제출하지 않음.
