# 02. Agent Platform 독립 제품 PRD

## 2.1 제품의 완료 정의

**Field 설치 파일·계정·서버·DB가 전혀 없는 환경**에서 사업자가 가입하고 정보를 등록·승인한 뒤, AP 상담 링크 또는 자신이 소유한 외부 사이트에 위젯을 설치하고, 별도 고객 기기의 실제 문의를 받아 사람이 답변하며, 유료 구독·해지·데이터 내보내기까지 진행할 수 있어야 한다.

AP 사업자는 초기에는 조직 1개·대표 AI 1개라는 제안 한도로 시작한다. 추후 다중 AI 확장에 대비해 agent_id를 두되 초기 UI에서 불필요한 에이전트 편성을 요구하지 않는다. 서비스·제품 안내는 지원하지만 재고·주문·배송·결제의 실시간 자동 처리를 연결 없이 제공하지 않는다.

## 2.2 필수 사용 흐름

| 순서 | 화면과 행동 | 저장·검증 |
|---|---|---|
| 1 | AP 홈페이지 → 내 사업 AI 만들기 | Field 가입 링크로 강제 이동 금지 |
| 2 | 이메일 또는 카카오 가입 | AP 자체 사용자·조직·세션·체험 생성 |
| 3 | 상호·소개·서비스·지역·영업시간·FAQ 등록 | 초안, 입력 출처, 미확인 정보. 사이트·예약 설정 불필요 |
| 4 | AI 이름·말투·안내 범위·사람 연결 설정 | AgentDraft, 조직 권한 |
| 5 | 답변 테스트 | 근거·미등록 질문·인계 확인; 실제 고객 알림/리드 생성 금지 |
| 6 | 검토 후 활성화 | KnowledgeRelease와 AgentRelease의 AP 내부 검증 |
| 7 | 상담 링크 공유 또는 외부 설치 | 운영 주소·허용 도메인·상태 확인 |
| 8 | 고객 상담 → 이름·번호로 문의 제출 | AP의 원본 대화/비회원 접근 권한 |
| 9 | AP 문의함에서 사람 응대 | AI 중지·답변·알림·고객 복귀 |
| 10 | 필요하면 외부 서비스 연결 | 선택 기능. 연결 전에도 1~9 정상 운영 |

최초 고객 문의 전에는 문의 0건을 그대로 표시한다. 예시 고객·허위 후기·가짜 정확도·매출 그래프를 채우지 않는다. 사이트가 없어도 상호와 서비스 소개가 있는 독립 상담 랜딩 화면을 제공한다.

## 2.3 AI가 사용하는 데이터

지식 원본은 AP 직접 입력 또는 승인된 외부 커넥터의 구조화 데이터다. `source_kind=native|connector`, `source_id`, `external_entity_id`, `source_revision`, `content_hash`, `approved_by`, `approved_at`를 보관한다.

Field 연결 후 해당 서비스의 가격·운영시간은 Field 원본을 참조한다. AP 화면에서는 ‘Field에서 관리’로 표시하고 같은 필드를 직접 수정하지 못하게 한다. AP 고유 FAQ와 말투는 AP에서 편집할 수 있다. 직접 입력 데이터와 연결 데이터가 같은 대상을 설명하면 출처 매핑·우선순위를 확인한 후 연결하며 자동 덮어쓰기·단순 이름 일치 병합을 하지 않는다.

| 객체 | 역할 |
|---|---|
| KnowledgeDraft | 비공개 입력·수정·가져온 변경안 |
| KnowledgeRelease | 승인된 불변 지식 묶음; 사이트 ID 불필요 |
| KnowledgeSource | 외부 연결·마지막 검증 시각·승인된 소스 버전·동기화 상태 |
| AgentRelease | 말투·허용 기능·안내 문구·정책 버전 |
| Deployment | 자체 링크·소유 사이트 위젯·제휴 카드 등 설치 위치 |
| Conversation / Submission | 고객 대화와 최종 제출된 연락 요청 |
| ActionRequest | 고객이 확인한 외부 업무 전달 요청. 예약 원본이 아님 |

AP 직접 입력 지식의 상호·서비스·FAQ는 작성 중 빈 값도 비공개 초안에 서버 저장해 재접속 후 이어 쓴다. 고객 공개와 AI 근거에 쓰는 KnowledgeRelease는 필수 값을 다시 검사한 뒤 사업자가 별도로 승인한다. 자동 저장 실패·오프라인·revision 충돌은 저장 완료로 표시하지 않고 입력을 보존한다. 공개 버전 번호와 직접 입력 초안 번호는 별도로 관리한다.

가격·예약 가능성은 추측하지 않는다. Field 연결 데이터가 최신 승인 상태인지 확인할 수 없으면 해당 조건의 확정적 안내와 예약 도구를 중단하고 사람 문의로 전환한다. 세부 최신성·승인 규칙은 연동 계약 4.5절을 따른다.

## 2.4 기본 AI와 도구

| 기능 | 기본 AP 단독 | 외부 연결 시 |
|---|---|---|
| 상호·서비스·FAQ 안내 | 승인 AP 정보 조회 | 승인된 연결 데이터도 출처 검증 후 이용 |
| 문의 초안 | 고객 발언·선택 서비스 정리 | 동일 |
| 정식 접수 | 고객의 제출 버튼과 서버 검증 후 AP 저장 | 동일 |
| 사람 인계 | AP 문의함으로 전환 | 허용받은 Field 관리실에도 API로 표시 |
| 예약 시간 조회 | 기능 비노출 | 활성 커넥터의 제한 API로 조회 |
| 예약 요청 전달 | 기능 비노출 | 고객 확인 후 ActionRequest → Field 요청 |
| 예약 확정·가격 변경·할인·결제 | 금지 | 연결되어도 금지 |

LLM은 tenant·권한·금액·발신자를 결정하지 않는다. 서버가 고정한 agent/조직/지식 버전으로 검증된 도구만 호출한다. 고객 메시지나 외부 기사 내용이 공식 지식·정책·새 도구가 되어서는 안 된다. 임의 URL fetch·SQL·shell·외부 메일 보내기는 도구에 없다.

답변은 답변문, 사용 근거 ID, 지식 버전, 미확인 항목, 사람 인계 제안으로 구조화한다. 모델의 비공개 사고과정은 저장하지 않는다. 이름·번호·상세 주소는 모델 입력에서 최소화하며 고객 사진은 초기 비전 분석으로 보내지 않는다.

## 2.5 설치 상품 — 기본 위젯과 광고 카드를 분리

### 기본 설치: AP Core 필수

AP 대표 상담 링크, QR, 웹사이트용 버튼·플로팅 위젯·인라인 대화 중 검수된 기본 렌더러를 제공한다. 초기 프리셋은 한 엔진의 `floating`과 `inline` 두 표시 모드로 충분하다. 고객이 준비할 것은 직접 도메인 소유/설치 권한을 확인하고 발급된 설치 코드를 넣는 일이다.

Field도 동일 코드 로더·공개 배포 ID·허용 도메인 검증을 사용한다. Field에만 AP 서버의 내장 컴포넌트를 직접 import하거나 비밀키로 우회하는 경로는 없다. 로더 실패 시 원래 Field 문의·전화·예약 버튼은 남는다.

```html
<!-- 예시 계약. 실제 운영 host와 검증된 public deployment ID로 발급할 것. -->
<script async src="https://embed.agent-platform.example/sdk/v1.js"
        data-deployment="dep_public_example"
        data-mode="floating"></script>
```

`.example`은 실제 배포 주소가 아니다. 스크립트에는 운영자 API 토큰을 넣지 않는다. 위젯은 API용 단기·대화 범위 세션을 발급받고 원본 사이트의 고객 데이터나 DOM 전체를 수집하지 않는다. 테마·크기·대표 질문만 제한된 옵션으로 받는다.

자기 사이트의 고객지원 위젯은 광고 캠페인 생성을 요구하지 않는다. 모든 접점은 사업자명과 AI 안내를 표시한다. **‘광고’ 표시는 유료/스폰서 콘텐츠의 홍보 카드에 필수**이며, 일반 고객지원 위젯을 광고상품으로 강제 분류하지 않는다.

### 제휴 매체 배포: Distribution 릴리스

홍보 카드의 초안·공개·중지, 매체 도메인·광고 위치, 사업자의 배치 요청, 매체의 정확한 카드 버전 승인, 외부 대화→AP 안전 접수, 집계 성과를 제공한다. Firsthand의 모든 광고 네트워크 기능을 재현한다고 표현하지 않는다.

카드의 가격은 승인 서비스에 바인딩한다. campaign release 변경 시 새 버전 승인이 필요하며, 기존 승인을 최신 버전으로 바꿔치기하지 않는다. 위험한 사실 변경은 관련 노출을 보류한다. 부모 매체에 이름·번호·사진·대화·세션 비밀값을 반환하지 않는다.

## 2.6 외부 대화와 비회원 접수

외부 iframe에서는 일반 안내와 서비스 선택을 한다. 연락처·사진·상세 주소를 받는 양식은 AP의 1차 상담 도메인에서 제공한다. 고객이 외부 채팅에 식별정보를 직접 입력할 가능성도 고려해 마스킹과 보존을 적용한다. 개인정보가 전혀 들어오지 않는다고 가정하지 않는다.

전환은 단기·1회·대상 바인딩된 handoff 권한으로 처리한다. 제3자 쿠키가 없다는 이유로 실패하거나 로그인부터 요구하지 않는다. 브라우저의 외부 쿠키 제약을 고려한 설계다.[S05]

기존과 같이 회원가입·휴대전화 OTP 없이 이름·번호로 접수한다. 번호는 미인증으로 표시한다. 최초 접수 브라우저의 대화 범위 HttpOnly/Secure 세션과 별도 접수 확인키를 사용하고, 알림 링크/번호만으로 원문·사진·과거 기록을 공개하지 않는다. 확인키는 문자·알림톡에 포함하지 않는다. 다른 브라우저에서 확인키가 필요할 수 있는 불편과 번호 오입력의 잔여 위험을 명시한다.

같은 대화에서 AI→사람 문의→외부 업무 요청으로 넘어갈 때 원문과 선택 정보를 보존한다. 외부 업무 전송에는 수신 사업자·외부 제품·전달 필드·요청 상태·필요 처리 안내를 보여주고 명시적 제출을 받는다. 자동으로 Field 가입 계정이나 고객 프로필을 만드는 것은 금지한다.

상담 링크에서 모델 공급사 또는 예산 설정이 없어도 익명 AP 대화 원본을 열어 사람 문의를 이어갈 수 있어야 한다. AI 답변 시도는 실제 차단 상태로 표시하고 실패한 질문을 고객이 확인·수정할 수 있는 사람 문의 초안에 남긴다. 초안 5,000자 한도로 질문을 더하지 못하면 추가됐다고 안내하지 않고, 원 질문 입력과 누락 안내·초안 축소 뒤 재추가 경로를 유지한다. 고객 동의 후 같은 원본·배포 귀속을 유지하며, 연결된 외부 업무 요청은 같은 화면에서 별도 현재 조건 확인과 동의를 거친다.
고객이 AI 질문을 건너뛰고 바로 사람 문의를 제출해도 상담 링크의 활성 배포에 귀속된 AP 원본으로 접수한다. AI 질문과 사람 제출이 동시에 시작되면 한 상담 세션을 공유하며, 사람 접수 뒤 늦게 도착한 AI 답변은 표시하지 않는다.

상담 링크와 외부 iframe의 AI 질문 POST `/v1/engagements/{id}/messages`는 질문마다 임의의 `Idempotency-Key`를 보낸다. 같은 대화·키·질문은 모델 실행과 사용량을 다시 만들지 않고 완료 답변, 진행 중 202, 확정 실패를 재사용하며 같은 키의 다른 질문은 409로 거절한다. 응답이 유실되면 유효한 상담 세션에서 GET `/v1/engagements/{id}/messages/recover`와 같은 키로 상태를 조회한다. 진행 중·조회 장애에는 성공을 표시하거나 새 질문을 실행하지 않는다. 브라우저 탭의 임시 재시도 원장에는 질문 원문 대신 해시와 키만 둔다. 서버의 실행 상태가 5분 이상 `in_progress`이면 GET과 같은 키 POST 재시도는 조회 시점 `result_unknown`을 반환한다. 이는 실패 확정이나 재실행 허가가 아니다. 원래 실행은 여전히 새 키 질문을 막으며 늦은 완료를 같은 키로 다시 확인할 수 있다. 고객에게는 결과 미상·상태 재조회·사람 문의를 안내한다.

## 2.7 상담 원본과 사람 응대

AP에서 시작한 대화 원본은 AP DB에만 있다. AP 관리실에서 열든 Field가 정식 API로 보여주든 같은 conversation_id와 message sequence를 사용한다. Field UI에서 작성한 답변도 AP 서버가 저장·모드 전환·알림 생성까지 담당한다.

`ai_assisting → needs_owner → human_active → waiting_customer → closed`를 기본 상태로 한다. 고객이 추가 답변하면 다시 needs_owner로 연다. spam 상태는 대화·증빙 보존정책과 별도로 발송을 중단한다. 사람 응대 진입과 답변 저장을 원자적으로 처리하고, 생성 중인 AI는 마지막 전송 전에 automation_paused와 revision을 다시 검사한다.

원문, 요약, 미확인 값, 고객 공개 답변, 내부 메모를 분리한다. 내부 메모는 외부 매체와 고객 응답 스키마에서 제외한다. AP 장애 시 Field가 AP 답변을 성공으로 표시해서는 안 된다. 로컬 입력은 전송되지 않은 초안으로 남기고 복구/재전송 선택을 제공한다.

## 2.8 AP 알림·사용량·구독

단독 AP는 자체 카카오톡·웹 푸시 사업자 알림과 고객 카카오→실패 문자 대체를 가진다. Field의 메시지 Worker가 없어도 동작해야 한다. 두 제품이 같은 공급사를 쓰더라도 발송 주체·계약 적합성·템플릿·사용량 원장은 구분한다. AP 업무 알림은 직접 접수·미해결 인계·고객 추가 답변에 한하며 단순 질문에는 보내지 않는다.

AP 구독으로 AI 응답·상담실·기본 외부 설치를 사용할 수 있다. 예약·사이트 기능을 구매해야만 AP 결제를 진행할 수 있으면 실패다. 기본 상담 설치는 매체 요금제와 분리한다. 체험 14일, 대표 AI 1개, 유료 월 500회 AI 응답 등은 운영비 검증 전 제안값이다. **독립 AP 가격은 새 plan version으로 정하고, 기존 Field 통합안의 29,000원을 자동 적용하지 않는다.**

원가·동의가 확정되지 않은 플랜은 test mode에서만 결제한다. production은 승인된 가격·세금·갱신·해지 조건 없이는 유료 판매를 활성화하지 않는다. 이는 추가 사용자 설문이 아니라 출시 가격 확정 작업이다.

AP 해지 시 신규 AI·신규 접수·새 캠페인을 제한해도 기존 상담의 정리·내보내기 경로를 유지한다. Field 구독은 해지되지 않는다. 이미 Field에 접수된 예약은 Field에서 계속 처리하며, AP를 다시 구독해야 예약을 볼 수 있게 만들지 않는다.

## 2.9 역할별 화면

| ID | 역할/화면 | 핵심 요소 |
|---|---|---|
| AP-P01 | AP 제품 홈 | AI 만들기·외부 설치·요금·매체·로그인 |
| AP-O01 | 가입·빈 관리실 | 이메일/카카오, 시작/이어서 하기, 데모 분리 |

| AP-O03 | AI 설정·테스트 | 이름·말투·허용 도구, 근거·상태·실제 활성화 |
| AP-O04 | 문의함·대화 | 직접 답변·사람 인계·미인증 번호·알림 실패 |
| AP-O05 | 공유·설치 | 링크·QR·소유 도메인·설치 코드·테스트·중지 |
| AP-O06 | 연동 앱 | 권한·출처·Field 연결·재동의·해제·실패 |
| AP-O07 | 홍보 카드 | 초안·미리보기·공개·버전·배치 |
| AP-O08 | 성과·사용량 | 대화/접수/외부 전환 구분, 실제 수금은 아님 |
| AP-O09 | 구독·계정·데이터 | 별도 요금/동의/해지·export·삭제 |
| AP-C01 | 고객 상담 랜딩/위젯 | 상호·AI 고지·공개 안내·사람 문의 |
| AP-C02 | 안전 접수/후속 대화 | 이름·번호·사진·확인키·외부 요청 상태 |

매체는 자기 도메인/위치/카드 승인과 집계만 본다. 사업자와 매체 역할을 같은 사람에게 허용하더라도 별도 membership으로 확인한다. AP 관리자라는 이유로 Field DB나 예약 관리자 권한을 주지 않는다.

## 2.10 AP 원본 데이터와 내부 API

AP 전용 DB: `ap_users`, `ap_identities`, `ap_organizations`, `ap_memberships`, `ap_knowledge_sources`, `ap_knowledge_drafts`, `ap_knowledge_releases`, `ap_agents`, `ap_agent_releases`, `ap_deployments`, `ap_conversations`, `ap_messages`, `ap_submissions`, `ap_visitor_grants`, `ap_action_requests`, `ap_connector_bindings`, `ap_campaigns`, `ap_campaign_releases`, `ap_publishers`, `ap_slots`, `ap_placement_approvals`, `ap_events`, `ap_outbox`, `ap_notifications`, `ap_usage`, `ap_subscriptions`, `ap_invoices`, `ap_audit`.

표의 `ap_`는 소유권을 명확히 하기 위한 명세 접두어이며 DB가 제품별로 나뉘면 실제 테이블 접두어는 ADR로 생략 가능하다. Field 외부 ID는 string 메타데이터이며 AP의 FK가 아니다.

| 계약 | 핵심 동작 |
|---|---|
| POST /v1/organizations | AP 조직·체험 생성 |
| PATCH /v1/knowledge/draft | revision 조건 수정, source 필드 통제 |
| POST /v1/knowledge/releases | 사업자 승인 버전 생성 |
| POST /v1/agents / POST /v1/agents/{id}/activate | 사이트·예약 없이 개설·활성화 |
| POST /v1/agents/{id}/tests | 테스트 격리, 근거 반환 |
| POST /v1/deployments | link/owned_embed/partner 구분, 권한·허용 origin |
| POST /v1/public/deployments/{id}/sessions | 짧은 공개 대화 세션, 관리자 토큰 금지 |
| POST /v1/engagements/{id}/messages | 승인 정보·모드·비용 검사 |
| POST /v1/engagements/{id}/handoffs | AP 1차 접수 권한 교환 |
| POST /v1/conversations/{id}/submissions | 최종 제출, 비회원 capability |
| GET/POST /v1/conversations/{id}/messages | 권한/actor 구분, human reply와 AI 실행 분리 |
| POST /v1/action-requests | 고객이 확인한 외부 작업 요청 저장 |
| POST /v1/subscription/checkout / cancel | AP 구독만 처리 |

내부 API와 위임 공개 API의 이름이 비슷해도 인증 주체·스코프·응답 허용 필드를 분리한다. 교차 제품 호출에는 연동 계약의 전용 경로를 사용한다.
