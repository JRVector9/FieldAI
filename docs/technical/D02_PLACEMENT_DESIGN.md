# D02 정확한 카드 버전 배치 승인 설계 — 2026-09-24

## 경계

`TASKS.md` D02, AP PRD 2.5, QA90~QA96을 적용한다. 사업자의 카드 공개와 매체의 배치 승인은 별도 의사결정이다. 배치는 AP가 소유하며 `campaign_release_id`와 `publisher_slot_id`를 변경하지 않는다. 매체에는 광고 카드의 승인 문구만 제공하고 고객 연락처·사진·대화·세션 비밀은 제공하지 않는다.

## 상태·권한

- 사업 조직 owner는 현재 공개 중인 정확한 CampaignRelease와 활성·검증된 매체 slot으로 배치 요청을 만든다. 같은 release/slot은 하나의 요청만 허용하고 같은 재시도 키/본문은 같은 ID, 다른 본문은 409다.
- 매체 조직 owner는 자기 slot의 `requested` 배치만 `approved` 또는 `rejected`로 결정한다. 승인 직전에 캠페인의 현재 공개 release/승인 지식, slot 상태·DNS 검증, 예상 release/hash를 다시 확인한다. 바뀌었으면 409로 최신 카드의 새 요청을 요구한다.
- 사업 조직 owner는 요청/승인 배치를 `cancelled`로 중지할 수 있다. 매체 owner는 승인 배치를 `suspended`로 중지할 수 있다. 거절·취소·중지된 행은 slot 재활성화로 자동 승인하지 않는다.
- 공개 배치 조회는 `approved` + 현재 캠페인 release + 승인 지식 문구 일치 + slot active + 도메인 검증 유효일 때만 카드 내용을 반환한다. 카드 초안·새 release는 기존 배치 승인 내용을 갱신하지 않는다.
- AP 공개 `/placements/[id]`는 이 조회 결과로 승인 카드를 미리 보여준다. D03 설치 코드가 발급되면 배치에 귀속되는 AP 상담으로 연결하고, 발급 전에는 상담 준비 상태를 표시한다.

## 데이터·실패/복구

`ap.placements`에 사업 조직·캠페인·불변 release, 매체 조직·slot, 요청 hash/재시도 key hash, 상태·결정 actor/시각/사유를 기록한다. DB 유일 제약이 중복 요청을 막는다. 사건은 AP 사업 outbox와 매체 outbox에 각각 최소 ID/상태만 기록하며 고객 원문을 넣지 않는다. 결과 미상 재시도는 같은 key로 원래 결과를 조회한다. 공개 조회는 안전하지 않은 상태를 404로 숨긴다. 실제 제휴 매체 origin 설치/광고 대화/성과는 D03/D04다.
