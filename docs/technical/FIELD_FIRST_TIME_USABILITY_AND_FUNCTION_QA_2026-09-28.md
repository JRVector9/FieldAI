## 첫 사용 경로 관찰

- 홈 `/`: `내 홈페이지 만들기`와 `무료로 시작`은 Field로 이동한다. 동시에 상단/본문의 AI 카드·`AI만 도입하기`가 첫 화면에서 크게 보인다. AP 웹을 끈 Field 단독 실행에서는 AI 링크가 도착하지 않는다. AI가 선택 기능이라고 텍스트는 설명하지만 화면의 시각 우선순위가 초보자의 첫 목표(홈페이지 공개)보다 앞서 보인다. 이 평가는 화면 관찰에 기반한 UX 가설이며 실제 사용자 인터뷰 결과는 아니다.
- 로그인된 미공개 사업장의 `/workspace`: 화면 맨 위 주 CTA는 `AI 상담 연결`이다. 홈페이지 상태는 `초안/공개 전`인데 `사이트 수정하기`는 화면 오른쪽 아래 카드에 있다. 이 배치에서는 첫 사용자가 다음 행동을 AI 연결로 오인할 가능성이 있다. 직접 문의/예약은 AP가 없어도 가능하다고 안내한다.
- `서비스`→`사업 정보·공개 관리`: 승인 전 초안의 필수 상호·서비스 이름·소요 시간·FAQ 문답이 비어 있으면 `현재 초안 승인`이 비활성화되고 하단에 필수 조건이 표시된다. `revision 1`/`카탈로그`/`승인 버전` 같은 내부 용어가 첫 이용자에게 그대로 보인다. 승인 후 고객 화면에 반영된다는 설명은 존재한다.
- 사이트 제작 1단계 `사업 정보 편집 열기`의 실제 목적지는 `/workspace` 첫 화면이다. 사용자는 거기서 다시 `서비스`→`사업 정보·공개 관리`를 열어야 입력 폼에 도달한다. 사이트 제작 도중 편집기로 돌아가는 경로도 바로 제시되지 않는다. `site-editor.tsx`의 링크가 `href="/workspace"`임을 확인했다.
- 사이트 제작 5단계는 `승인된 카탈로그: 없음`을 보여 주고 `현재 초안 공개`를 비활성화한다. 공개 불가 조건별 설명/해결 링크는 버튼 곁에 없다. 버튼의 조건은 승인 정보, 초안 revision, 미저장 변경, 권한/작업 상태와 이미 공개된 revision의 조합이라서 이용자는 무엇을 고쳐야 하는지 판단하기 어렵다.
- 사이트 제작 1단계의 `디자인 복구로 되돌리지 않습니다`와 편집기·예약 관리의 `revision`은 내부 구현/저장 개념을 그대로 노출한다. 사업자에게 필요한 메시지는 ‘무엇이 고객에게 보이는가’와 ‘다음에 무엇을 해야 하는가’다.
- 문의함의 빈 상태는 ‘사이트 준비하기’ 경로를 준다. 예약·일정은 두 방식과 수동 전화 예약을 표시하지만 `승인 카탈로그: 없음`, `수동 일정 차단` 등 초보자에게 뜻이 불명확한 표현이 있다. 기존 미공개 초안을 수정·승인·공개하거나 실제 고객을 대신해 문의/예약을 제출하지 않았다.
