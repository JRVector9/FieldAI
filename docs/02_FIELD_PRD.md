# 03. Field 독립 제품 PRD

## 3.1 Field의 책임

Field는 사업자 스스로 사이트를 개설하고 고객의 직접 문의와 예약을 운영하는 제품이다. AP는 선택적으로 설치하는 외부 서비스다. Field 홈페이지·일반 문의·예약·구독의 요청 경로에서 AP가 상시 필수 호출이 되어서는 안 된다.

Field 자체 사이트 제작 AI는 Field의 제작 기능으로 유지한다. 상담용 AI 설치와 제작용 LLM 호출은 비용·권한·상태를 명확히 구분한다. 관리실의 ‘AI 연결’은 AP 계정·AI·권한을 연결하는 화면이지 AP 전체 관리 콘솔의 복제본이 아니다.

## 3.2 기존 5단계 셀프 사이트 제작

**플랫폼 홈 → 가입 → 빈 시작 화면 → 사업 정보 → 디자인 → 편집 → 연락·예약 → 확인·공개 → 운영실 오늘**.

| 단계 | 필수 동작 |
|---|---|
| 사업 정보 | 상호·업종·서비스·지역·소개·운영시간·연락처·사진 입력; 서버 초안 |
| 디자인 | 템플릿 또는 AI 설명; 입력한 실제 상호·서비스로 생성 |
| 편집 | 글·사진·alt·색·허용 폰트·페이지·섹션 순서·직접/AI 수정 |
| 연락·예약 | 사이트 직접 문의, 전화, 두 예약 방식, 사업자 카카오/푸시 설정; AP 연결은 선택 |
| 확인·공개 | 기본 주소, 모바일, 필수 정보, 미승인 변경 확인; 실제 공개 후 성공 표시 |

AP 연결 전에도 사이트를 공개할 수 있다. 설치를 권하는 카드에 ‘나중에 연결’ 경로를 두며 AI 상담이 없는 상태의 버튼은 ‘문의 남기기’로 명확히 표시한다. 비연결 상태에서 AI가 답하고 있다고 표시하지 않는다.

Essential·Editorial·Warm 3개 배치는 색상만 바뀌는 동일 레이아웃이 아니다. 한 페이지 기본 사이트와 서비스·소개·작업 사례·FAQ 등 최대 5개 소개 페이지 시작안을 유지한다. 시스템 문의·예약 화면은 소개 페이지 수와 별도다. 사진 없는 사업자도 개설할 수 있다. 이미지 생성·외부 이미지 자동 수집은 제외한다.

## 3.3 편집·저장·공개·복구

`FieldBusinessDraft/FieldCatalogRelease`와 `SiteDraft/SiteRelease`는 Field 내부 객체다. 초안은 서버에 자동 저장하고 base_revision 충돌을 검사한다. 약 1초 저장 디바운스는 제안값이다. 오프라인/실패 중에는 저장 완료라고 표시하지 않는다. 입력 중인 빈 상호·서비스명·소요시간 0도 비공개 사업정보 초안에 저장해 재접속 후 이어 쓸 수 있다. 필수 정보가 미완성인 초안은 사업자가 승인할 수 없고 고객 공개 버전에도 반영하지 않는다.

AI 생성 작업은 queued/running/proposed/applied_to_draft/failed/canceled/stale를 구분한다. 실제 LLM 결과를 제한된 페이지 JSON으로 검증한 뒤 초안만 수정한다. 생성 중 직접 수정하면 오래된 AI 결과를 자동 덮어쓰지 않는다. 실패·취소·재시도에 입력과 사진을 잃지 않는다.

Field 내부에서 승인한 사업정보·사이트 공개는 해당 DB 트랜잭션/작업 상태로 일관성 있게 적용한다. **AP로의 동기화 성공까지 Field 공개 트랜잭션에 넣지 않는다.** 성공 후 outbox로 승인 정보 변경을 발행하고 별도 ‘AI 정보 동기화 대기/검토 필요’ 상태를 보인다.

과거 디자인 복구는 초안으로 가져오고 재승인 후 공개한다. 현재 서비스 가격·예약 조건·확정 예약은 디자인 복구로 되돌리지 않는다. 사실 복구가 필요하면 별도 변경 승인이다. AP AI/배포 중지는 사이트 디자인 복구로 해제되지 않는다.

## 3.4 도메인·공개 자산

기본 슬러그와 자체 도메인 기능은 유지한다. 자체 도메인은 등록·소유 증명·DNS·TLS·연결·대표 URL을 구분하며, 실패 시 기본 주소를 유지한다. 도메인 구매·갱신 판매는 제외한다.

AP 위젯을 Field 자체 도메인에 붙일 때도 새 origin 승인이 필요하다. Field의 도메인 검증 사실을 숨은 DB로 전달하지 않고, 공식 커넥터의 signed source/공개 검증 엔드포인트 또는 AP가 지원하는 일반 소유 검증으로 확인한다. 기본 플랫폼 호스트는 정확한 사업자 서브도메인 단위로 제한한다. 전체 플랫폼 `*` 허용으로 다른 사업자가 설치키를 재사용하게 하지 않는다.

사이트 공개 사진과 비공개 문의 첨부는 저장 정책을 분리한다. HEIC 등은 안전한 변환, 실제 파일 형식 검사·용량·EXIF 제거를 거친다. 공개 릴리스가 참조하는 사진은 초안에서 삭제했다고 즉시 제거하지 않는다.

## 3.5 AP 연결 화면

Field 메뉴: **더보기 → 연동 서비스 → AI 상담 연결**. 이미 고객 사이트가 공개돼 있든 개설 중이든 별도 설정할 수 있다.

```text
AI 상담 연결
제공 서비스: Agent Platform (별도 서비스)
[기존 계정 연결] [AI 서비스에 가입]

공유할 정보: 승인된 사업 소개·서비스·가격·FAQ
설치할 위치: 이 Field 사이트의 검증된 주소
선택 권한: Field 문의 전달 / 예약 시간 조회·요청 / 대화 조회·답변
요금: Field 이용료와 AP 이용료는 별도. 연결만으로 결제하지 않음.
```

권한·기관·연결 조직·AI를 명확히 표시한다. 허용하지 않은 기능은 숨기거나 권한이 필요하다는 이유를 표시한다. 연결 실패/일부 동의/검토 필요/정보 오래됨/중지/만료를 ‘연결됨’ 하나로 뭉개지 않는다.

AI 위젯은 AP 공식 SDK로 설치한다. 설정 화면에는 연결 상태·마지막 동기화·AI 테스트·AP 관리실 열기·연결 해제를 둔다. AP의 홍보·매체·전체 구독 메뉴를 Field 내부 소유 기능처럼 복제하지 않는다.

## 3.6 Field 자체 문의와 연결된 AI 문의

| 구분 | Field 자체 직접 문의 | AP에서 시작한 AI 문의 |
|---|---|---|
| 대화 원본 | Field | AP |
| 고객 후속 대화 | Field 상담 도메인 | AP 상담 도메인 |
| 관리실 표시 | Field DB에서 조회 | 위임 API 조회; 요약 인덱스와 업무 링크만 Field에 저장 |
| 사람이 답변할 때 | Field 메시지 저장·알림 | Field BFF → AP 위임 답변 API → AP 저장·알림 |
| AP 장애·연결 해제 | 정상 이용 | 원문 재조회/전송 불가 표시; 이미 접수된 Field 업무는 유지 |
| 예약 원본 | Field | 연결 요청이 수락되면 Field |

사업자에게는 문의 목록을 한 화면에서 보여줄 수 있지만 행마다 `Field 직접 문의`/`외부 AI 상담` 출처를 표시한다. 연결 조회 장애를 전체 문의 0건으로 표시하지 않는다. AP 문의를 보기 위해 Field 전체 관리 권한을 AP에 넘기거나 AP의 모든 채널 대화를 Field에 노출하지 않는다. 기본 범위는 **이 연결/배포/외부 업무에 관련된 AP 대화만**이다.

Field는 AP 대화의 전체 원문을 상시 복제하지 않는다. 업무 수행에 필요한 연락처·고객 제출 요약·서비스·희망일·승인한 첨부는 고객 확인 후 받은 작업 스냅샷으로 보관한다. AP 대화 원본과 별개로 그 수신 시각·목적·출처·보존기간을 기록한다. 요약 미러의 최신 시각과 상태도 표시한다.

AP 연결이 해제되면 그 원문/답변 권한은 사라진다. 기존 Field 업무 처리·달력·제출된 연락 정보는 정당한 보존 범위에서 남는다. 원래 대화를 무단으로 복제해 연결 해제를 우회하지 않는다.

## 3.7 예약·달력의 원본

기존 희망시간 제출형과 시간표 선택형을 모두 제공한다. 각 서비스는 기본 방식을 상속하거나 선택할 수 있으며 사이트 생성 과정이 서비스별 선택을 덮어쓰지 않는다.

시간표는 사업자 1명의 공통 자원, 소요·준비·이동시간, 영업시간·휴무·예외일, 최소 요청 여유와 기간을 적용한다. 모든 서비스가 같은 자원을 공유한다. 미확정 요청은 슬롯을 독점하지 않고, 확정·수동 차단만 점유한다. 동시에 들어온 요청은 승인 시 DB에서 최종 충돌을 검사한다.

고객이 서비스나 날짜를 바꾸면 이전 조건의 가능 시간 선택을 즉시 해제한다. 조회 실패·시간표 미설정·빈 결과에는 현재 서비스와 날짜를 유지한 재조회 경로를 제공하며, 이미 입력한 고객 연락처와 동의는 보존한다. 가능 시간을 다시 조회해도 예약은 요청 단계이며 사업자 확정 전 점유로 표시하지 않는다.

| 상태 | 점유 | 처리 |
|---|---|---|
| requested | 없음 | 확정/시간 제안/거절/고객 철회 |
| proposed / customer_accepted | 없음 | 새 조건에 대한 고객 동의, 사업자의 최종 승인 |
| confirmed | 있음 | 완료·변경 요청·취소 요청 |
| change_requested / cancel_requested | 기존 점유 유지 | 새 합의와 승인 후 교체/해제 |
| completed / canceled / rejected / expired | 과거 기록 | 결과 표시; 임의 자동 노쇼 처리 금지 |

AP는 예약 가능 시간을 읽고 요청을 만들 수 있으나 confirm 권한이 없다. Field 사용자의 명시적 승인만 일정 확정 API를 실행한다. 제안을 고객이 수락해도 자동 확정되지 않는다.

`[start-before_buffer, end+after_buffer)` 범위에 같은 resource의 겹침을 차단하고 예약 상태·점유·outbox를 한 Field DB 트랜잭션에 저장한다. 수동 일정도 예외가 아니다. 시간 변경 때 기존 점유를 먼저 삭제한 뒤 실패하는 상태를 만들지 않는다. 과거 가격·소요시간은 접수/확정 당시 스냅샷을 유지한다. 시간은 timezone 포함, 표시 기본은 Asia/Seoul이다.

## 3.8 알림·구독·장애

Field 직접 문의·예약 알림은 Field가 발송한다. AP에서 시작한 연결 대화의 고객 알림은 정상 연결 중 AP가 발송하며, Field는 해당 사건을 이벤트로 전달한다. 이미 발송된 같은 사건을 두 제품이 각각 카카오/문자로 보내지 않는다. 상세 규칙은 연동 계약 4.8절을 따른다.

Field의 유료 이용은 사이트·직접 문의·예약·도메인·자체 알림을 기준으로 독립 제공한다. 과거 통합 가격 29,000원+부가세는 최종 가격이 아니며 분리 후 구성 변경에 맞춰 재확정한다. AP를 구독하지 않아도 Field 결제가 가능해야 한다. 연결 동의는 별도 제품 결제 동의가 아니다.

해지 시 이미 확정된 미래 예약과 종결 중인 업무의 정리/내보내기 경로를 유지한다. 일반 정리 30일, 예약은 마지막 예정일+7일 등 기존 제안값은 법무·운영비 검수 후 확정한다. Field를 해지해도 AP 계정·독립 AI·다른 사이트 설치를 자동 해지하지 않는다.

AP 장애 시 고객에게 Field 직접 문의/예약과 전화 경로를 제공하되, AP의 기존 미전송 내용을 몰래 복사해 새 문의를 만들지 않는다. 고객이 새 요청을 제출하면 `fallback_origin`과 관계를 기록하고 가능한 요청 ID로 중복 후보를 보여준다. 같은 전화번호만으로 두 대화를 자동 병합하지 않는다.

| ID | 화면 | 변경점 |

| F-O01~07 | 가입·빈 시작·5단계·개설 완료 | 기존 셀프 제작 보존; AP 연결은 선택 |

모바일은 오늘/문의/예약/내 사이트/더보기 유지. 매체 관리실은 Field 메뉴에서 제거하는 것이 아니라 AP 제품으로 소유권을 옮긴다. 필요하면 AP로 이동 링크를 제공하되 Field 관리자 세션으로 자동 열람하지 않는다.

## 3.10 Field 데이터·API

Field DB: 사용자·조직·사이트·서비스·카탈로그 릴리스·공개 미디어·직접 대화·접수·예약·점유·알림·구독·감사. 연결 데이터는 `field_integrations`, `external_work_requests`, `external_thread_refs`, `source_mappings`, `inbox_events`, `outbox_events`, `revocation_jobs`로 분리한다. AP PK는 문자열 참조이며 cross-DB FK가 아니다.

Field 자체 API는 기존 사이트/문의/예약 경로를 보존한다. 외부에 제공할 `facts`, `capabilities`, `availability`, `external-requests`, `external-request-status`는 별도 integration API로 만들고 요청마다 조직·연결·허용 도구·리소스·현재 상태를 검증한다. AP 토큰만으로 Field 사용자 세션이나 예약 확정 권한을 대신하지 못한다.
