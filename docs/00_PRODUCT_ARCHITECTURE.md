# 01. 최종 제품 구조와 변경 기준

**기준일 2026-09-24 · 개발 계획 v3.0 · 이전 개발안 v2.0을 대체**

> 독립 AI 플랫폼은 누구나 가입해 자기 사업 AI를 만들고 외부에 설치하는 제품이다. Field는 그 AI 플랫폼의 내부 상위 서비스가 아니라, 공개된 연동 계약으로 AI를 설치하는 첫 번째 외부 고객 서비스다.

## 1.1 문서의 적용 수준

| 구분 | 의미 |
|---|---|
| 사용자 확정 | 기존 21개 선택, 사업자 셀프 홈페이지 제작, 역할별 화면 유지, Firsthand식 독립 AI 제품, Field의 외부 연동 관계 |
| 실행 설계 | 추가 설문 없이 개발 에이전트가 구현할 수 있게 정한 제품 경계·상태·API·데이터·오류 처리. 변경 시 ADR과 영향 검토 필요 |
| 제안값 | 기간·한도·성능·보존·집계 하한. 실측이나 가격 확정이 아니며 정책 설정으로 관리 |
| 출시 게이트 | 실제 계정·PG·메시지·도메인·보안·복구·연동 검증과 책임자 승인 |
| 이번 산출물 | 개발 문서와 계약 예제. 운영 서버 코드, 새 UI 프로토타입, 실제 공급사 승인 결과가 아님 |

`Agent Platform` 또는 `AP`는 독립 AI 제품의 임시 명칭이다. 최종 상표·도메인이 아니다. Firsthand는 브랜드 AI·외부 배포라는 제품 개념의 참고 대상일 뿐, Firsthand API 구매·코드 이용·기능 완전 동등성을 전제하지 않는다.[S06]

우선순위는 **최신 사용자 확정 → 이 v3.0의 명시 규칙 → 개정된 제품별 명세·연동 계약 → 과거 시안의 시각 표현**이다. v2.0의 공유 DB·공유 조직·한 구독·통합 출시 의존성과 UI v3의 하나의 역할 전환기는 더 이상 운영 아키텍처 기준이 아니다.

## 1.2 두 제품, 한 공개 연동 계약

| 항목 | Agent Platform — 독립 AI 서비스 | Field — 사이트·업무 운영 서비스 |
|---|---|---|
| 핵심 고객 | 기존 사이트 운영 사업자, 자체 사이트 없는 사업자, 기업, 제휴 매체 | 다양한 1인 사업자, 이후 기존 출장·AS 업체 |
| 첫 행동 | 내 사업 AI 만들기 / 내 사이트에 설치하기 | 내 홈페이지 만들기 |
| 자체 제공 | 승인 지식, AI, 상담 링크·위젯, 상담 관리실, 사람 인계, 홍보·매체, 사용량·구독 | 사이트 제작·수정·공개, 서비스 정보, 일반 문의, 예약·달력, 알림·구독 |
| 선택 연결 | Field 등 외부 업무 서비스 | 외부 AI 플랫폼 설치·권한 설정 |
| 단독 동작 | Field 서버·DB·계정·예약·구독 없이 전 과정 이용 | AP 서버·DB·계정·구독 없이 사이트·일반 문의·예약 운영 |
| 장기 확장 | 다양한 외부 서비스의 커넥터와 AI 배포 인프라 | 견적·기사 배정·현장 작업·증빙·청구·사후관리 |

```text
Agent Platform                                Field
자체 계정 / 자체 사업 조직                      자체 계정 / 자체 사업 조직
사업 AI / 승인 지식 / AI 상담 원본              사이트 / 서비스 / 직접 문의 원본 / 예약 원본
자체 구독 / 메시지 / 매체 운영                   자체 구독 / 메시지 / 현장 업무
             └──────── 공식 API·위젯·웹훅 ────────┘
                         동일 계약
              일반 외부 홈페이지 / 제휴 매체 / 다른 연동 앱
```

두 제품이 같은 회사에서 운영되어도 예외 내부 API, 상대 DB 접속, 공통 세션 쿠키, 고객별 수작업 설치를 전제로 하지 않는다. 초기에는 같은 인프라 장비를 활용할 수 있지만 독립 배포와 논리 격리는 유지한다. 같은 장비에서 발생할 공통 장애까지 제거됐다고 주장하지 않는다.

## 1.3 독립성 불변조건 — 구현 중 임의 변경 금지

| ID | 필수 조건 |
|---|---|
| B01 | AP를 배포할 때 Field DB·마이그레이션·환경변수·서버를 요구하지 않는다. |
| B02 | Field를 배포할 때 AP DB·마이그레이션·환경변수·서버를 요구하지 않는다. |
| B03 | AP와 Field는 별도 사용자·조직·membership·로그인 세션·서명키를 가진다. 같은 이메일로 자동 연결하지 않는다. |
| B04 | DB·마이그레이션·런타임 계정·큐·파일 접근권한·암호화 키·백업은 제품별이다. 상대 테이블 JOIN/FK/직접 SQL 금지. |
| B05 | Field 커넥터는 외부 통합자와 같은 정식 API·범위·승인·비용·속도 제한을 사용한다. |
| B06 | 가입·AI 활성화에 사이트·캠페인·매체·예약 설정을 강제하지 않는다. |
| B07 | AI 없이도 Field의 원래 일반 문의·예약·고객 연락은 이용 가능해야 한다. |
| B08 | 전체 상담 원본과 업무 요청 원본의 소유를 분리한다. 같은 대화를 양쪽에서 독립적으로 수정하지 않는다. |
| B09 | 승인 정보의 제품 간 반영은 비동기 계약이다. 공유 DB의 원자적 전환이나 항상 즉시 동일 상태를 약속하지 않는다. |
| B10 | 연결·연결 해제·AI 중지·사이트 비공개·각 제품 해지는 서로 다른 동작이다. |
| B11 | 각 제품은 독립 구독 원장과 별도 출시 게이트를 가진다. 묶음 요금과 공유 크레딧은 이번에 자동 도입하지 않는다. |
| B12 | 기존 고객·사업자/서비스 제공자·매체·관리자 역할을 보존하되 제품별 권한으로 분리한다. |

## 1.4 사이트 제작 AI와 고객 상담 AI를 구분한다

**Field의 ‘사이트를 만들어주는 AI’는 Field 소유의 제작 도구다.** 기존의 템플릿 + AI 제작 결정을 지키기 위해 Field 자체 LLM 어댑터로 페이지 JSON 변경안을 만든다. AP의 고객 상담 런타임을 호출하거나 AP 구독을 요구하지 않는다. LLM 공급사 SDK 같은 무상태 유틸리티 코드는 재사용할 수 있지만 키·사용량·호출·작업 기록은 분리한다.

**고객이 ‘AI에 문의하기’를 누를 때 작동하는 AI는 AP의 외부 설치 기능이다.** Field는 승인된 설치 구성과 공개 위젯만 이용한다. 새 AI를 Field DB에 만들어 고객 상담을 흉내 내지 않는다.

AP가 중단돼도 Field의 제작 AI는 AP 때문에 중단되지 않는다. 공통 LLM 공급사 자체가 장애인 경우에는 별도 외부 의존 장애로 표시하고 Field 템플릿·직접 편집을 유지한다.

## 1.5 기존 21개 결정의 귀속

| 번호 | 유지할 결정 | 제품/검수 귀속 |
|---|---|---|
| 01 | 다양한 1인 업종에 개방 | 두 제품. 전문 업종 업무를 모두 지원한다는 의미는 아님 |
| 02 | 템플릿 + AI 사이트 제작 | Field. AP 가입·사용과 무관 |
| 03 | 일반 문의 + 예약 요청 + 별도 관리실 | Field 자체 완결. AP는 자체 상담실, 예약은 연결했을 때만 |
| 04 | AI 채팅 + 문의 양식 + 예약 양식 | 연결된 Field에서 세 경로 제공. 미연결 Field의 직접 양식은 계속 제공 |
| 05 | 모바일·PC 웹, 네이티브 앱 제외 | 두 제품·매체·각 관리자 화면 |
| 06 | 사업자 카카오톡 + 웹 푸시 | 이벤트 원본 제품이 책임 발송. 중복 발송 금지 |
| 07 | 고객 이름·휴대전화, 회원가입·OTP 없음 | 각 원본 제품의 비회원 접수. 번호를 본인 식별자로 취급하지 않음 |
| 08 | 고객 카카오 실패 시 문자 대체 | 단일 알림 책임 제품에서만 적용 |
| 09 | 직접 처리할 업무만 사장님 외부 알림 | 양쪽 공통. 단순 AI 질의와 매체 노출은 제외 |
| 10 | 허용 구성요소 내 AI 사이트 제작 | Field. 임의 HTML·JS 생성 금지 |
| 11 | 여러 페이지, 한 페이지 완성도 가능 | Field |
| 12 | 기본 주소 + 자체 도메인 | Field 사이트. AP는 자체 공통 상담 도메인·외부 설치; AP 화이트라벨 도메인은 별도 후속 |
| 13 | 구조화 서비스 목록 | Field 원본 또는 AP 직접 입력 원본. 연결 시 출처·버전 매핑 |
| 14 | 희망시간 제출형 + 시간표 선택형 | Field. AP는 연결 기능으로 선택 노출 |
| 15 | 자체 달력 + 수동 일정, 외부 캘린더 제외 | Field. AP 자체 달력은 만들지 않음 |
| 16 | 누구나 가입·개설 | 두 제품 사업자. 위험 기반 제한과 매체 설치 검증은 별도 |
| 17 | 무료 체험 후 명시적 유료 구독 | 각각의 제품. 계정 연결만으로 상대 결제 시작 금지 |
| 18 | 고객의 서비스 대금은 플랫폼 외부 수령 | 두 제품 동일. 예약금·서비스 대금·매체 정산 제외 |
| 19 | 이메일 + 카카오 로그인 | 제품별 앱 설정·동의·세션. 동일 이메일 자동 병합 금지 |
| 20 | 직접 등록·승인한 정보·서비스·FAQ·정책만 AI 참고 | AP 직접 승인 및 Field에서 승인한 정보를 공식 커넥터로 가져와 검수. 임의 크롤링 제외 |
| 21 | 초안 저장 → 검토·공개, 복구 후 재승인 | Field 사이트 / AP 지식·AI·홍보 각각 적용 |

Field에 AP 연결이 없는 상태는 장애도 미완성 계정도 아니다. 단, 전체 연결 상품의 인수 테스트에는 AI 문의 경로가 실제로 설치되는지 검수한다. 독립 Field 출시를 전체 통합 완성으로 보고하지 않는다.

## 1.6 출시 단위

| 릴리스 | 내용 | 기다리지 않아도 되는 것 |
|---|---|---|
| A — AI Core | AP 가입·지식·AI·자체 상담·외부 위젯·알림·구독·운영 | Field 사이트·예약, 홍보 카드·매체 |
| F — Field Core | 사이트 제작·도메인·직접 문의·예약·알림·구독·운영 | AP 설치·매체 |
| I — Field Connector | 정식 연결·권한·지식 동기화·외부 설치·업무 전달·API 답변 | 제휴 매체 광고 기능 |
| D — Distribution | AP 홍보 카드·제휴 매체·승인·집계 | Field. 연결된 예약 전환 지표만 Field 이벤트가 있을 때 표시 |
| Suite | A+F+I+D의 전체 인수 및 제품별 독립 회귀 | 없음. 전체 최종 범위의 완료 판단 |

Firsthand식 대화형 홍보·매체 기능을 삭제하는 것이 아니다. **기본 외부 설치가 매체 기능의 개발을 기다리지 않도록 출시 단위를 분리**한다. AP Core부터 독립적으로 검증하고, Field Core는 병렬 개발하며, 매체는 AP의 확장으로 제공한다.

## 1.7 범위 밖

현재 단계에서 범용 AI 에이전트 마켓, 고객 서버 온프레미스 설치, 임의 도구/MCP 실행, 브라우저 자동 수집, 웹 문서 자동 학습, 이미지 생성·진단, AI 전화, 고객 서비스 대금·예약금 결제, 광고 자동 입찰/거래소, 매체 광고비 정산, 리타게팅·고객 프로필 판매, 다인 기사 배정 UI는 만들지 않는다. 공개 API는 문서화된 설치·상담·제한된 커넥터 계약이며 무제한 외부 실행 권한을 판매하는 제품이 아니다.
